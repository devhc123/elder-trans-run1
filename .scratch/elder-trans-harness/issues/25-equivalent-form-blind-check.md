# 25 — 等价形式负例的教师盲检

**What to build:** 等价形式负例的标签语义是一个判断，不是一条可程序化证明的规则，所以在它进
训练集/验收集之前先用教师盲检验证一次。

**要验的到底是什么**：原文写「每3天复查」，注入句里出现「三天」，我们标 False。依据是红线
定义——"判的是这个候选有没有原文依据"，值相同即有依据。但注入句**周围的措辞**未必逐字成立
（source 里的「3天」可能说的是"连服3天"而不是"每3天复查"）。这个判断站不站得住，得问教师，
不能自己说了算。

**样本量与来源**：**train / holdout 各 25 条，共 50 条**。两侧都抽是因为两个切分的原文分布
不同，只抽一侧证不了另一侧。50 这个数不是拍的——`LITERATURE.md` L3 的判读规则已经预注册过
"≥50 条人工抽检一致性 ≥95%"，与既有规则对齐。

**三档预注册动作（现在写死，不许看到数字再定）**：

| 一致率 | 动作 |
|---|---|
| ≥95% | 全用（训练池 + 对抗子集） |
| 90–95% | **只在训练池用，不进对抗子集**，并在票据里写明这次降级及理由 |
| <90% | 完全弃用，回退到只有 grounded 注入负例 + 探针汇报 |

中间那一档是有意义的：训练池里混进几条错标的代价是稀释，冻结验收集里混进几条错标的代价是
整个 L2 门槛的数字不可信，两者不该同一个标准。

**分开派发、分开落盘**，不与 ticket 23 那两批合并。三批的用途完全不同（那两批是训练/验收
**数据**，这批是**质量门**），混进同一个文件会让"这条标注当初为什么产生"不可追溯——项目里
`verifier/labels/*.jsonl` 一直是按来源分文件的。盲性靠 prompt 保证（不透露批次身份、不透露
我们认为它是负例），不靠混批：等价形式那 50 条本来就是注入句，跟真实答案混在一起也藏不住。
