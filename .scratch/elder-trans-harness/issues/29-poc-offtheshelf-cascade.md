# 29 — POC：现成小模型 + deepseek 级联，$0 决定该训哪个

**What to build:** 这张票**已经跑完了**，记录结果。它回答的是一个在花训练钱之前
就该回答的问题：**现成的 ollama 小模型能不能当级联第一段？如果不能，该训哪个？**

用户的判断（2026-08-14）：「ollama 有很多小模型、可以随意组合、HF 还能 ollama pull
一些。和 deepseek 组合、测试后，再判断哪些小模型要训练。」——这正是 `DISCIPLINE.md`
D1.2 的 POC 判据：**验证想法成不成立，不是先把规模堆上去**。

## 方法

- **80 条**，从 silver-ref holdout 池确定性分层抽样（正 40 / 负 40；正例按红线比例、
  负例按「是否列表序号」比例）。**量小是刻意的**——POC 要的是大到不用统计就能看见的
  信号（D1.2）。
- prompt 用的是**小模型将来要用的那一份**（`SYSTEM_CANDIDATE` + `build_candidate_prompt`），
  否则数字换不到那条链上。
- 两轮跑**逐条相同**的 80 条，所以能**离线拼级联**，不用重复调 deepseek。
- 复现：`.scratch/elder-trans-harness/research/poc_{deepseek,ollama,cascade}.py`，
  原始逐条判定同目录 `*_result.json`。

## 三条结论

### 1. 零样本没有一个能当第一段，但失败模式分三类——这比分数有用

- **不敢报**：qwen3.5:0.8b（漏 97.5%）、medgemma:4b（漏 80%）
- **全报**：minicpm5（误 80%）、minicpm-v4.6:1b（误 80% 且漏 37.5%）
- **答非所问**：med-guard 输出自己的安全 schema（`Safety: Safe / Categories: None`），
  根本没回答这个问题。**它那行 100% 漏报是表格算出来的假象，不是它的能力**——
  它是为别的任务微调的，没参加这场考试。

**这恰恰是"需要微调"最干净的证据**：不是模型没能力，是**判定倾向没对齐**，
而对齐倾向正是微调最擅长、也最便宜的那种。

### 2. 级联的漏报会叠加，误报会相乘

minicpm5 单独漏 7.5%，接上 deepseek 后变成 **12.5%**——deepseek 会再漏一部分它送上来的。
所以**第一段的漏报预算必须比 5% 更紧**，不能刚好卡线。
反过来误报 80% → 30%，印证 SPEC 那条：**误报是成本旋钮，漏报是硬门**。

### 3. 微调候选的排序（有依据，不是拍脑袋）

- **首选 `openbmb/minicpm5`**（688MB、0.42s、最快）：唯一漏报接近门槛的（7.5%），
  缺的是把误报从 80% 压下来。**压误报比压漏报容易**——前者只要学会"什么不算违规"，
  训练集 6,518 条负例正是干这个的；后者要学会识别没见过的违规。
- **次选 `qwen3.5:0.8b`**：是原计划微调底座的同族，但零样本方向反了（几乎不敢报），
  微调要把它从保守扳到激进，而训练集正例只占 14.8%——**方向不利**。
- **出局**：medgemma:4b（慢且漏报高）、med-guard（schema 不匹配，除非重训，
  那就失去了"现成"的意义）。

## 过程中栽的坑（同一类，一天两次）

**推理模型的 token 预算被 thinking 吃光，`content` 返回空串，表象是"模型判不出来"。**

1. deepseek-v4-flash：`max_tokens=32` → **80/80 解析失败**，`finish_reason=length`，
   32 个 token 全是 reasoning。差点报成「deepseek 漏报 100%、这条路不通」。
2. ollama 上的 qwen3.5 / minicpm5：默认开 thinking，`num_predict=256` 同样被吃光。
   显式 `think=False` 后立刻干净输出 JSON，且 0.3–0.6s。

**共同点：失败长得像结论。** 两次都是靠去看**原始输出**才拦住的——只看聚合指标的话，
"漏报 100%"是个完全自洽、很有解释力的错误结论。
