# 24 — 两类注入负例的生成器

**What to build:** 两个新的合成器，产出**与合成正例同模板、同位置、同措辞**的负例。这是问题③
修复的核心：让"这句是不是注入的"这个特征本身不再携带标签信息。

**一、grounded 注入负例**：往 `verdict=pass` 案例的答案里注入 source_text 里**确实存在**、
且不在原 answer 里的实体/数字，标 False。实测供给充足：train 8,036 个实体 + 358 个数字可用，
holdout 2,091 + 90，93% 的 pass 案例都能造。

**二、等价形式注入负例**：原文写「每3天复查」，注入句里出现「三天」——候选 span「三天」在原文
有依据（值相同、只是形式不同），标 False，但它**不是** grounded（字符串对不上）。这是唯一能
压住合取捷径「在括注内 ∧ 不在原文里 → 违规」的那类负例，也正是真实池里最常见的难负例形态
（教模型 grounding 是语义不是字符串匹配）。实测可用：train **1,040** 条、holdout **208** 条。

**措辞绝对不能另起一套**——必须复用同一批 `TEMPLATES` 与同一个数字括注 wrapper、同一个末尾
追加位置。上一轮的教训就是这个：零候选安慰语只共享了前缀、内容另起一套，结果换了个特征
（位置）继续被破解。措辞一分叉，负例就又能被措辞特征认出来。

**硬不变量（代码断言 + 测试，不是注释）**：注入句里出现的**每一个** digit / cn_numeral /
fraction span 都必须有依据——grounded flavor 要求整段命中 source，equivalent flavor 要求其
等价形式命中 source——否则整条跳过。少了这条，会在一个标 False 的答案里塞进一个真违规数字，
那是货真价实的错标。

**正例产出必须逐字节不变**：这张票只加负例路径，不许顺手动到正例。用测试固化当前产出
（train 记录 红线0 314 / 红线2 198 → 候选 619 + 300；holdout 173 / 65 → 174 + 90）。
