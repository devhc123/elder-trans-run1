# 10 — 教师标注扩量到 3–5k（难例过采样）

**What to build:** 把教师标注从 500 条扩到 3–5k 条，作为正式训练集。

**采样策略按难度倾斜，不是从池子里均匀抽。** 教师是 Claude subagent，吞吐远低于 API 批量调用，实际能拿到的标注量是几千条量级而不是几万条——在这个预算下，均匀采样是浪费：大部分样本模型本来就判得对，学不到东西。要过采样的是难例：

- 09 摸底中 verifier 与教师判断分歧的样本类型
- 红线违规的正例（天然稀少，但漏报率门槛卡得最严，样本不足直接导致学不会）
- 术语密集、剂量条件分支、禁忌带例外、多药相互作用这类结构复杂的源文本

同时保持 verifier 训练池与测试集 `record_id` 零交集不被破坏。

从这批里留出 **300–500 条 held-out** 作为验收集，`record_id` 与训练集不交——**验收集必须现在就切出来并封存**，不能等训练完再从剩余数据里挑，那等于自己给自己划及格线。

**Blocked by:** 09（摸底结论决定扩到多少、往哪个方向倾斜）

**Status:** ready-for-agent

- [ ] 教师标注总量达到 3–5k，全部符合 schema 且通过 evidence 子串校验
- [ ] 采样按难例倾斜，倾斜依据与比例有据可查（不是均匀抽）
- [ ] 红线违规正例占比足以支撑 ≤5% 漏报率的训练目标
- [ ] 300–500 条 held-out 验收集切出并封存，与训练集 `record_id` 零交集
- [ ] 全部标注的 `record_id` 与测试集零交集（脚本验证）
