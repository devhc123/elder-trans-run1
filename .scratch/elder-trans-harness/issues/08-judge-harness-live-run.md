吞吐：**270 题拆约 20 个 subagent 并发**，每个批判 13–15 题，返回结构化 JSON 数组。串行不可接受。

判官 prompt **固化成文件**，不许在 subagent 里临时改——rubric 骨架取自 `/Users/chenhao/ClaudeCode/eqbench-run1/SOURCE/rubric_core3.yaml`（同理心 / 校准顺从 / 专业信任三维，0–20 分锚点，「专业信任」已含 `elder_communication` 子项）。

**判官不可复现，只能可审计——这个降级必须落实成证据留存。** session 内的 Claude 没有可钉版本的 API model id，换个 session 重跑就是另一批数。所以每次判官调用都要逐条落盘 `{case_id, 判官输入全文, 判官输出全文, 时间戳, 判官标识}`，run_id 写进 kpi.yaml。对外表述从「可复现」改为「可审计」——数字重跑会漂，但每一条判定都能被人翻出来核。可读性 KPI 是确定性计算，不受此影响。

产出：strict / glossed / strict_2500 三口径达标率（词级微平均，主报 strict）+ Wilson 95% CI + 场景宏平均 + **hard 子集分** + 忠实性通过率 + 逐题审计。

**不设长度护栏**——该能力独立调用，扩长是允许的方向。但字数与转译/原文字数比要一并输出，供观察。

## 这一轮真跑最重要的发现

**可读性 97.4% 与忠实性 64.5% 的落差，是靠编造买来的。**

字数比中位 1.89、P90 4.72——模型在大幅扩长。

**⚠️ 一处必须更正的结论。** 判官只判完 200 题时，分档呈现出漂亮的单调剂量-反应
（最短档 38% → 最长档 68%），我据此报告了「原文越薄编造越多」的干净因果。
**全集 270 题判完后，单调性不成立：**

| 原文长度 | 忠实通过（200 题时） | **全集 270** |
|---|---|---|
| 40–165 字 | 38% | **51%** |
| 168–310 字 | 75% | 73% |
| 316–580 字 | 69% | 73% |
| 596–1196 字 | 68% | **62%** |

| 扩长比 | 全集忠实通过 |
|---|---|
| 0.3–1.2x | 69% |
| 1.2–1.9x | 64% |
| 1.9–2.9x | 76% |
| **2.9–15.6x** | **51%** |

**站得住的部分**：最短原文（51%）与最高扩长比（51%）确实是两个最差档，明显低于
其余的 62–76%。薄原文诱发编造这条成立。

**不成立的部分**：中间档并非单调过渡，且**最长原文档也掉到 62%**——那多半是另一种
机制（长原文覆盖不全导致漏项，而非编造）。把这说成"扩长比与忠实性单调负相关"是
过度解读部分样本。

教训：200/270 的部分样本虽然总体均值几乎没偏（64.5% vs 64.8%），**分档趋势却完全
可以是假的**。分层结论必须等全集。

## 按场景（全集）

| 场景 | 忠实 | 要点覆盖 | 可读性 |
|---|---|---|---|
| 权益匹配 | **0%** | 62% | 0.966 |
| 用药咨询 | 32% | 63% | 0.969 |
| 用药干预 | 45% | 68% | 0.943 |
| 科普辟谣 | 53% | 81% | 0.960 |
| 饮食营养 | 57% | 85% | 0.943 |
| 医嘱转译 | 60% | 71% | 0.954 |
| 运动与养生 | 67% | 72% | 0.928 |
| 分科导诊 | 72% | 76% | 0.947 |
| 复诊与随访 | 82% | 79% | 0.965 |
| 日常照护 | 83% | 88% | 0.955 |
| 急症处置 | 90% | 64% | 0.963 |
| 检验报告解读 | 92% | 64% | 0.946 |

**可读性与忠实性几乎不相关**：用药咨询可读性最高（0.969）而忠实性倒数第二（32%）；
运动与养生可读性最低（0.928）忠实性却有 67%。这正是两个指标必须并列的证据——
任何一个单独都不能代表质量。

**两种失败形态可以分开**：急症处置/检验报告解读是「不踩红线但漏要点」（忠实 90%+
而覆盖仅 64%）；饮食营养是「覆盖到了但踩红线」（覆盖 85% 而忠实 57%）。前者是保守，
后者是越界，对 verifier 是两类不同的判别目标。

**权益匹配 15/15 全挂**，是全集里唯一一个零通过的场景。

> **⚠️ 这条归因错了，已更正。** 我原先报成「模型把医保『否』说反」，判官也是这么判的。
> 但 fable-5 的判官审计、以及两个独立的教师标注 agent，各自发现了同一件事：
> **该类原文是没有字段名的裸 DB 行**——开头孤零零一个「否」，文本里没有任何线索
> 表明它指医保：
>
> ```
> 否
> 根据不同医院，收费标准不一致，市三甲医院约（5000——10000元）
> 药物治疗、支持性治疗
> ```
>
> 任何读者拿到这段都不可能知道「否」指什么。被测系统把它读成「不是这个病」
> 「不严重」「不传染」——**那不是转译失真，是输入缺陷**。这 15 题测的是 schema 猜谜。
>
> 已在 `extract_candidates.py` 加 `FIELD_LABELS`，多字段拼接时渲染成
> 「是否医保报销：否 / 大致费用：… / 治疗方式：…」。该类需重新抽取、重写、重判。

A 类五条：**医保「否」被说反 ×3**（其中两条把原文治愈率 70%/65% 当成报销比例、编出"自己掏三成"）；**编造停药阈值**「收缩压 90 以下」（原文只说"血压过低"）；**把「不宜吃」说成「可以吃」**。

按场景，忠实性差异极大：权益匹配 0%（原文最薄）、用药咨询 25%、用药干预 45%、饮食营养 61%、日常照护 83%、急症处置 93%。

**反谄媚红线几乎未被踩**——模型的问题不是顺着老人说，是自己往里填东西。

## 修掉的一个会让整轮失真的配置错误

首轮（live-001）11 题输出为空、13 题被静默截断，合计 9% 样本是脏的。根因：`max_tokens=1500`，而 **deepseek-v4-flash 是推理模型，该额度包含推理 token**——那 11 题 `reasoning_tokens` 恰为 1500，正文一字未出。截断的 13 题更危险：会被当正常样本计分并压低分数且不报错。

已提到 8000 并显式捕获 `finish_reason`。重跑 270/270 全 `stop`，零空零截断（实测 `reasoning_tokens` 最大 4777、中位 202）。已加回归测试。
