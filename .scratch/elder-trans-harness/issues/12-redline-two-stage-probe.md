# 12 — 红线判别两段式重构：规则候选抽取 + 逐候选判定（探针轮，零 GPU）

**What to build:** 按研究阶段结论（`docs/RESEARCH_verifier_data_scarcity.md`、
`LITERATURE.md` L1–L3）把红线判别从「2B 生成式 JSON 联合判断」重构为两段式：
段 A 规则候选抽取（召回优先）→ 段 B 逐候选判定「该词/数在 source 里有没有依据」。
本票只做**零 GPU 探针**：证明两段式的召回上界和段 B 的判定质量，产出「要不要
按此架构立项正式轮」的书面答案。**本票不做任何 LoRA/GPU 训练**（L3 判读规则：
红线正例 <500 不予立项微调轮；探针不受此限因为不训练）。

**门槛（立项时写死，不许跑完再定）：**

| 探针 | 门槛 |
|---|---|
| P1 段A候选抽取 v1（词表∪数字∪中文数词∪食物扩展） | holdout instance 级（官方 `eval_verifier.py` 口径）红线 0+2 候选召回 **≥95%**（即漏报 ≤5%）；case 级误报率不设门槛（段 B 负责精度），但必须如实报告 |
| P2 教师逐候选判定对照臂 | 分层抽 ≥100 个候选（含全部两类：命中/未命中 gold evidence），教师判定与 gold 的一致率 **≥90%**；单候选判定成本（tokens）记录在案 |
| P3 合成最小编辑对试产 | 试产 ≥200 条合成正例（只用 train 切分的 source）；教师抽检 50 条，「确属违规」比例 **≥95%**；与真实 66 条正例的模式分布对比表（防单一模板坍缩）如实报告 |

P1 过线 + P2 过线 ⇒ 短期路线成立（规则段 + 教师在线判候选可直接当生产 verifier）。
P3 过线 ⇒ 中期路线成立（合成扩到 ≥1000 正例后立项段 B encoder 分类头训练轮，
届时按 L1 判读规则设分池验收 + 伪影对照臂）。任一不过线，结论照实写，不改门槛。

**污染纪律（研究笔记 §一.3 已预警）：** P1 的词表扩展与中文数词正则**只准在
train 切分的 miss 模式上调**；holdout 对每个冻结配置只评一次，评完即封。
今天研究阶段那次 holdout 评测（R1∪R2 漏报 7.4%）算作基线披露，不算调参。

**验收纪律（延续）：** 绝不报红线总准确率；漏报/误报分列；P2 一致率按
「候选命中 evidence / 未命中」两层分别报，防多数类假象（同 κ 的教训）。

**Blocked by:** 无（研究阶段已完成；本票不依赖 GPU）

**Status:** 三探针全部跑完。P1 通过（漏报2.0%），P3 通过（100%确属违规），
P2 未通过（82.5%，诊断为评测方法近似偏差，非教师质量问题）。中期路线
（合成扩量+段B训练）达成立条件；短期路线需先重跑一版干净的 P2 才能定论。

- [x] P1：候选抽取器 v1（`jargon.txt` + 阿拉伯数字 + 中文数词正则 + 食物/日常名词
      词表扩展；扩展只用了 train 切分 miss 检查——vt-0138/vt-0160 驱动了食物词表
      与中文数词正则，禁止看 holdout）；冻结后 holdout 一次性评测：
      **TP=147 FN=3 FP=781 TN=67，漏报率 2.0%（门槛 ≤5% → 通过）**，误报率 92.1%
      （不设门槛，如实报告，精度留给段 B）。剩余 3 条 FN（可的松、鱼蛋奶、
      鲤鱼草鱼）已记录，未回头调 wordlist 重评。实现：`verifier/redline_candidates.py`
      + `verifier/redline_food_wordlist.txt` + `verifier/redline_candidates_eval.py`。

      **`/code-review` 发现一处真实召回 bug**：数字/中文数词的"是否已在原文"
      判定原来用朴素子串（`"12" in "112"` 为真），会把一个真正编造的数字误判
      成"原文已有"而漏掉——source"不超过112"、answer 编成"别超过12"这种情形，
      旧代码完全测不出来。已改为整段精确匹配（对 source 里的数字/数词单独
      建集合，候选必须整体命中集合里的某一项才算"已有依据"，词表词不受影响，
      中文复合词的子串关系通常仍是同一实体，沿用子串判定是对的）。加了两条
      回归测试。重新跑冻结评测：**holdout 数字/漏报数字与修复前完全一致
      （TP=147 FN=3 FP=781 TN=67，漏报率仍 2.0%）**——这次修复没有改变
      P1 的结论，但堵上了一个会让漏报率被低估的口子，train 集上确实多测出
      10 条之前被误判为"已有依据"的候选（FP 2543→2553），如实记录。
- [x] P1 附带：候选抽取用的是已组装好的 `train/holdout.jsonl` `input` 字段
      （`parse_case_text` 解析），不涉及从 DB 多字段拼接 source_text，因此没有
      调用 `join_fields()`——这条待办是对着 handoff 坑 #4 预防性列的，但 P1/P3
      都只读已落盘的 jsonl，不触碰 DB 拼接路径，该坑不适用，特此说明而非静默
      跳过。若未来某个方向需要从 DB 重新抽取候选源文本，届时仍要走 `join_fields()`。
- [x] P2：教师逐候选判定 prompt 固定（含 TEACHER_TASK.md 红线 0 例外条款），
      3 个独立 agent 盲判 holdout 分层抽样 120 候选（正例60/负例60）：
      **总一致率 82.5%（门槛 ≥90% → 未通过）**，正例一致率 90.0%（单独达标），
      负例一致率 75.0%（拖累总分）。人工审计全部 21 条分歧后诊断：负例分歧
      15 条全部是教师给出的合理判断，根因是派生 gold 只对齐案例级标注里**一条**
      evidence 子串，而案例级 schema 每条红线只记一个例子，不穷举同一红线下的
      多个违规词——candidate 级判定比案例级标注更细粒度，暴露的是评测方法本身
      的近似误差，不是教师质量问题。正例分歧 6 条里 1 条（"心痛定"即案例主药）
      揭示红线0例外条款的应用存在**跨次判断噪声**，2 条是候选文本与不相关
      evidence 字面重合的巧合，1 条是 P1 抽取器自身已知的词法局限（不回头改，
      冻结纪律）。**门槛未过，如实记为未通过，不做门槛软化**；但诊断表明
      真正该改的是下一轮的评测方法（穷举式候选级复核），不是教师判断质量。
      token 成本：三批合计 331,509 tokens / 731s，120 候选，均 2,763 tokens/候选
      （探针期 agent 全套工具栈开销，非生产边际成本估计）。实现：
      `verifier/judge_candidates.py` + `verifier/score_teacher_judgments.py`。
- [x] P3：最小编辑对合成管线试产 **293 条**（train 切分，≥200 门槛已过；同一条真实
      answer 只追加一处"类别→具体值"注入，不改写原文任何一字——L1 伪影规则）；
      模式分布已核：13 种示例对（防坍缩到单一模板，但 77.1% 落在兜底对"阿司匹林/
      布洛芬"上——类别关键词词典覆盖不全，多数触发走了兜底，如实记录，词典本身
      未回头扩充——那属于下一轮的活，不是本探针）；教师抽检 50 条（独立盲判，

      **`/code-review` 发现并修复了三处问题（细节见下方「code review 修复」）**，

## 汇总：三探针结果 + go/no-go

| 探针 | 门槛 | 实测 | 结论 |
|---|---|---|---|
| P1 候选抽取召回 | ≥95% | **98.0%**（漏报2.0%） | **通过** |
| P2 教师逐候选一致率 | ≥90% | 82.5%（正例90.0%/负例75.0%） | **未通过**（诊断：主因是评测方法用单条 evidence 子串做候选级 gold 的近似偏差，不是教师质量问题——见上方 P2 详情） |
| P3 合成正例确属违规 | ≥95% | **100%**（50/50） | **通过** |

**P1 + P3 过线，P2 未过线（如实记录，不软化门槛）。**

按票头预定义的判定规则："P1 过线 + P2 过线 ⇒ 短期路线成立"——P2 未过线，
**短期路线（规则段+教师在线判候选直接当生产 verifier）严格意义上未达成立条件**。
但 P2 的诊断分析显示未过线的根因是评测方法的近似误差（案例级"单条 evidence"
标注被当候选级 gold 使用，系统性低估了教师的真实一致率），而不是教师逐候选
判断本身不可靠——21 条分歧人工审计里没有一条像是教师误用 rubric 或幻觉。
"P3 过线 ⇒ 中期路线成立"——**中期路线（合成扩到 ≥1000 正例后训练段 B）
达成立条件**：P1 证明规则段召回够用、P3 证明合成产物质量够高（100% 确属违规，
远超门槛），加上研究阶段 L1 的文献支持（FactCC 系规则合成对模板化违规是
已验证有效的做法），这条路线的两个前提都已用盘内数据验证过。

**建议的下一步（不在本票执行，需要用户拍板是否立项）：**

1. **短期**：不能直接照字面"P2 未过线"下结论"教师在线判候选不可用"——
   需要先用一轮**穷举式候选级人工复核**（不是从案例级标注反推）重新测 P2，
   这才是对"教师逐候选判定质量"的干净测量。这一步零 GPU、成本可控（约
   120 候选 × 教师复核），值得作为 P2 的重跑，而不是直接否决短期路线。

## 判读规则（从 LITERATURE.md 抄入，铁律 15 的硬产出）

1. **L3**：红线正例 <500 条时不立项任何微调轮；恢复训练前置条件 = 正例池 ≥1000
   且含真实困难样本锚定。教师在线判上线须固定 rubric + ≥50 条人工抽检一致性 ≥95%。
2. **L1**：未来训练轮的验收分池报告——真实违规留出集单独算漏报率，≤5% 门槛只认
   真实池；合成池与真实池漏报率差 >10pp 判「学到伪影」，逐条归因后重造。
3. **L2**：验收必设「医学正确但原文未给出」对抗子集（≥50 条），漏报率单独报告、
   门槛同总集；任何候选 checker 该子集不过线即判不可用。
4. **盘内**：红线 1 全池仅 2 例，不进两段式管线，教师全文判兜底，不指望蒸馏学会。
