# 05 — 候选抽取与按配比抽样

**What to build:** 从测试集池（03 切出的那份）抽出待撰写的源文本，按 04 定下的场景配比分配，每条带完整出处。

抽取逻辑按场景走不同字段：检验报告解读取 bdyd 检查库的「报告解读」与 dxys 检查库的「结果解读」、ylys 指标库；用药咨询取 others `drug_info`（禁忌/相互作用/警示/用法用量）与 ylys 药品信息（同类药对比）；饮食营养取 ylys 饮食指导（宜吃/少吃/慎吃）与 others `do_eat`/`not_eat`；分科医生取各库的就诊科室字段；复诊提醒取 `treatmentCycle`/`cure_lasttime`/`best_time`；权益匹配取 `yibao_status`/`medicalInsurance`/`cost_money`。

筛选口径必须体现「面向银发群体」：按老年高发病、老年常用药、老年体检套餐指标过滤，不是随机抽。

**每条候选必须带可回溯的 provenance**：库名、逻辑表、`record_id`（精确到 `文件#row号`）、取用的字段名、源站点。这是评测集可信度的基础——评审要能拿着一条题目翻回原始记录。

**医嘱转译这一类要特别标注。** 全盘没有真实医嘱单、处方笺、出院小结，这一类只能用疾病库的「治疗」「就医」字段模拟。候选记录里要打上标记，下游文档不得默认它是真实医嘱。

**Blocked by:** 03（record_id 三分切）、04（场景配比）

**Status:** done — `pipeline/extract_candidates.py`

- [x] 每个子场景产出候选池，规模足够按配比抽样后仍有余量
- [x] 抽样结果符合 04 的配比表，合计 270
- [x] 每条候选带完整 provenance，可随机抽查 10 条翻回原始记录逐字核对
- [x] 所有候选的 `record_id` 都落在测试集池内，与 verifier 训练池零交集（脚本验证）
- [x] 筛选体现老年导向，能说明筛选条件
- [x] 医嘱转译类候选带「模拟来源」标记


**结果：** 候选池合计 8,809 条，12 个场景全部抽满 270 题。最紧的是急症处置（48 候选 / 21 题），最富裕的是用药咨询（2,559 / 19）。

**实施中修掉的四个问题（均带回归测试）：**

1. **跨场景复用同一条源记录。** 去重原本只在场景内做，但 `bdyd/疾病` 一行同时有「治疗」「日常」「就诊科室」三个字段，会被医嘱转译、日常照护、分科导诊各抽走一次——三道题共享同一段原文，测试集实际多样性低于表面题数。改为**全局去重 + 稀缺场景优先分配**（按候选池从小到大排，否则富裕场景会把稀缺场景的记录抢空）。
2. **单字关键词造成子串假命中**：「钙」命中`降钙素`、「钠」命中`注射用头孢曲松钠`。改成 `血钙/补钙/血钠` 等不会误配的完整形式。
3. **正文残留 Python 列表字面量**：部分库把多值字段 `str(list)` 存了进去，`['药物治疗', '支持性治疗']` 原样出现在待转译原文里。清洗为 `药物治疗、支持性治疗`。
4. **权益匹配原文过薄**（中位 48 字，只有「否 / 收费约 X 元」）。并入治疗方式、疗程、检查项目等字段后中位升到 80 字。**这仍不是医保政策条款**，`thin_source` 标记保留。

**两处刻意的口径调整：**

- **急症处置**改用急症专属关键词表（跌倒/噎食/晕厥/烫伤/低血糖等），而不是整类豁免老年筛选。整类豁免会把「断指急救」这种明显偏工伤的条目抽进来；而通用老年词表在急救表上又几乎全不命中。列出老年高发急症类型是有依据的折中。
- **运动与养生免于「记录名命中」要求**：穴位叫`三阳络穴`、`颊车穴`，名字里不可能出现老年词，真正的信号在功效正文（该穴位主治失眠/高血压）。对这类场景强求记录名命中是错误的口径，但仍要求必须有正文命中依据，不无条件放行。

抽样优先取**记录名命中**的候选：`二甲双胍片`的用法用量，质量高于某个冷门药说明里恰好提到「糖尿病」。除豁免场景外，各场景记录名命中率均 ≥70%。
