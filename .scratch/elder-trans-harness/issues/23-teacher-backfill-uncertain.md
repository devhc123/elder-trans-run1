# 23 — 教师补标剩余的不确定候选

**What to build:** 把"不确定候选"（fail 案例里没命中 evidence、被可信池整条丢弃的那批）
剩下的部分补标完。问题二那轮只标了 train 352 条里的 100 条、holdout 874 条里的 150 条。

**为什么这是治本的一步**：捷径问题的根因是**正例里 88% 是合成的**。结构探针的 J 上限恒等于
这个占比——加多少便宜负例都只能从另一侧压，压不动这个上限，只有加真实正例才动得了。按第一批
100 条的实测比例（33% 判 violated）外推，train 侧 252 条能再拿约 83 条真实正例，真实正例
129 → 约 212，合成占比 88% → 81%，所有结构探针的 TPR 上限跟着从 0.877 掉到约 0.81。这是
L1 明确支持的方向（SAFE 的 848 条真实锚定先例）。

**两批的目的不一样，不要混着想**：

| 批次 | 条数 | 目的 |
|---|---:|---|
| train 侧 | **252**（352−100，**全量，不抽样**） | 改变训练分布：压低合成正例占比 |
| holdout 侧 | **200**（724 里确定性抽样，不是全部） | 把"同答案内区分度"切片从 59 个答案推到 100+ |

holdout 侧刻意不全标：真实 holdout 正例已有 241 条，0 漏报时 Wilson 95% 上界 1.5%，≤5% 门槛
的统计功效**已经够了**，扩它不改变判决力；扩的唯一理由是问题二那个区分度切片只有 59 个答案、
置信区间太宽。全标 724 条边际收益递减且量级是 train 那批的 3 倍。

**采样必须确定性，且按 `(case_id, candidate_text)` 排除已标注过的那批**——不能靠 rank 排除：
历史上那 250 条是一次性脚本抽的、脚本没入库，rank 对不上。新 id 不能与既有 id 撞。

沿用问题二那轮的盲评 prompt：不透露"这条来自丢弃池"、不透露我们认为它是什么，只给候选文本 +
source + answer + 红线0身份例外条款说明，直接问"这个候选在原文里有没有依据"——**不是从单条
evidence 反推**。4 agent 并行，落盘时**追加**到既有的
`verifier/teacher_candidates_{train,holdout}.jsonl`（同来源同文件）。

**不猜标签**：教师没判到的条目直接跳过，不给默认值（`apply_teacher_labels` 的既有设计原则）。
