# 0.8B 医嘱读析器（rxreader）能否让大模型的适老化医嘱翻译更忠实？——一天内从零交付到发布的复盘

> 项目：elder-trans-run1 ｜ 时间：2026-08-17 ｜ 结论：成立。0.8B 抽「必须保留 / 需要解释」两栏原文子串注给 deepseek，core80 盲评题级 55:21、忠实维度 159:67（噪声底 17:22），拿到 oracle 上限增益的大部分；本地 1.2 s/条；已发 HF 公开仓库 chenhaodev/rxreader-qwen3.5-0.8b。副产品：deepseek 一个标注 batch 烧 ¥48（thinking 占 95% token），定下每 batch ≤ ¥5 硬门。

---

## 1. 原始设想与转向

产品目标：医嘱/治疗说明 → 文化程度不高的老人听得懂的话，小模型 + 大模型两段配合。

此前 29 张票把小模型放在「段 B 红线判定器」（判大模型转译有无编造/漏关键信息，漏报硬门 ≤5%），需要 gold 标签、正负例配平、捷径探针、教师交叉复核，64 commit 后 0 个可用模型、0 个可跑翻译器。用户 2026-08-17 判断：太复杂，先发布小模型，形态学 eqreader（0.8B 抽情绪关键短语 → 注给大模型，40 题盲评 21:13 即发布）。

转向后的小模型岗位：**rxreader**，读【背景】老人档案 + 【医嘱】原文，输出两栏原文逐字子串——

| 栏 | 内容 | 管什么 |
|---|---|---|
| 保留 | 剂量 / 次数 / 频率 / 时间 / 数值区间 / 禁忌 / 必须就医条件 | 忠实性（不丢数字、不改数字） |
| 解释 | 老人听不懂、必须跟一句白话的术语 | 可读性 |

编排层：逐字子串校验（0.75 吸附）→ 空则不注入 → 背景槽只放档案事实。**hint 岗位错了只掉质量不伤安全**，所以 silver 标签（deepseek 打）够用，不需要 gold——这一条把 29 张票的纪律工作从发布前置变成发布后可选。

方法论纪律（用户设定 + 项目 DISCIPLINE）：先建判别力再训模型；POC 用大到不需要统计就能看见的信号；同窗口 A/B 先跑对照臂读噪声底；判据预注册；大模型 API 每 batch ≤ ¥5；RunPod 花钱前预检并确认。

## 3. S1：基线与噪声底（core40，3 判官）

题库 core40：从 270 题适老化医疗转译测试集（12 场景，每题带老人画像/提问/专业原文/应覆盖要点/红线，人工撰写并经审核）确定性分层抽样——医嘱转译 15、用药咨询 5、用药干预 5、检验报告解读 5、复诊随访 5、日常照护 3、饮食营养 2；难度 易 20 / 中 15 / 难 5。

判官：deepseek-v4-flash，题内随机换位（种子确定），三维投票（听得懂 / 说得对且全 / 分寸）+ 总体，同题 3 次合成多判官；另附确定性可读性（strict 达标率）。判官与生成同源，配对下两臂同受自偏好，只读相对胜负。

对照臂 = 同一 prompt、同一模型的两次生成（s1-baseline vs 早前 live-003）互判：

| 维度 | 臂 A | 臂 B | 平 |
|---|---|---|---|
| 听得懂 | 30 | 54 | 34 |
| 说得对且全 | 50 | 57 | 11 |
| 分寸 | 24 | 28 | 66 |
| 总体票 | 51 | 63 | 4 |
| 题级多数票 | 17 | 22 | 1 |

读数：题级 17:22 是纯噪声；可读性 strict 达标率两臂均 1.0（均值 0.9585 / 0.9588）→ 可读性在基线上已饱和，hint 的主战场只能是「说得对且全」。判据据此预注册：40 题 3 判官题级多数票 ≥27:13 且忠实维度净胜 ≥20，达不到加到 80 题再看，不加判官。eqreader 的 21:13 幅度在本任务上不构成证据。

## 4. S2-0：oracle hint 天花板（$0 级）

让 deepseek 用小模型将来的同一份指令抽两栏（rxreader_label.py，子串校验 + 0.75 吸附），注回 translate.py，与 S1 基线盲评：

| 维度 | 基线 | oracle-hint | 平 |
|---|---|---|---|
| 听得懂 | 53 | 54 | 12 |
| 说得对且全 | 24 | 83 | 12 |
| 分寸 | 20 | 49 | 50 |
| 总体票 | 30 | 84 | 5 |
| 题级多数票 | 11 | 29 | 0 |

副作用：hint 臂平均长 +12%（709 → 796 字）；耗时持平（15.6 vs 16.0 s）；可读性 1.0 → 0.95，掉的两题是药名反复出现（「奥美拉唑」5 次）。

读数：29:11 / 忠实 +59，两条判据都过，增益几乎全在忠实维度 → hint 这条路成立，目标变成「0.8B 复现 deepseek 的两栏标注」，验收仍是下游盲评而不是标注一致率。

## 6. S3：rxreader-v1 盲评

本地 ollama `rxreader-v1`（Q4，Modelfile 同 eqreader：空 think 块 + temperature 0 + think=false）：core40 均耗时 1.17 s，两栏皆空 0，非子串丢弃 30 / 371（8%）；与 oracle 逐字重合 keep 67/165、explain 122/256（边界差一两字居多，不作验收）。

| 集合 | 题级多数票（基线 : rxreader-v1） | 说得对且全 | 听得懂 | 分寸 |
|---|---|---|---|---|
| core40 | 11 : 26（平 3） | 30 : 81 | 53 : 47 | 20 : 35 |
| core40b（预注册扩样：用药咨询 8 / 用药干预 8 / 检验报告 8 / 复诊 6 / 日常照护 6 / 饮食 4；难度 易 12 中 25 难 3） | 10 : 29（平 1） | 37 : 78 | 43 : 52 | 25 : 39 |
| core80 | 21 : 55（平 4） | 67 : 159（+92） | 96 : 99 | 45 : 74 |

对照：噪声底 17:22；oracle 29:11 / +59。同 40 题 rxreader-v1 26:11 / +51 → 拿到 oracle 增益的大部分。可读性 strict 达标率两臂 0.975–1.0 持平。

判读过程：
- core40 首轮 26:12（平 2）。医嘱转译-007 的 hint 臂被 thinking 吃光 8,000 额度、正文半句截断（finish_reason=length，reasoning 7,650 tok），判官 3:0 判输。按 harness 既有规则（截断不得混进正常样本）加「截断自动升额度重试」后重生成一次、只重判该题 3 票拼回 → 26:11（平 3）；原始文件保留为 *_orig.json。
- 字面判据「≥27」差 1 题（净差 +15 已超 27:13 的 +14）。不动判据、不重跑判官，按预注册后备扩到 80 题 → core40b 29:10 → core80 55:21。

判官输的题（core40 3:0 判基线赢的 8 题）反面读数：判官理由多为「A 更口语、B 更贴原文但更用力/添加了原文没有的照护建议」——hint 让大模型更「守数字」，偶尔也更「多说」。

## 7. 端到端实拍（模型卡用例）

输入：80 岁女性、识字不多、高血压房颤；医嘱「阿司匹林肠溶片 100mg 每日一次 早餐前空腹口服；华法林钠片 2.5mg 每晚一次，定期复查INR，目标2.0-3.0；避免与布洛芬同服。」

rxreader-v1 输出（1.9 s）：保留 100mg、每日一次、2.5mg、每晚一次、2.0-3.0、避免与布洛芬同服；解释 阿司匹林肠溶片、华法林钠片、INR、布洛芬。

| | 无 hint | 带 hint |
|---|---|---|
| 剂量 | 「一次吃一片，也就是100毫克」「一次一片，也就是2.5毫克」——原文没有「一片」，是编出来的 | 「100毫克，每天吃一次，早饭前空腹吃」「2.5毫克，每天晚上吃一次」——六个硬信息原样放句首 |
| 术语 | 肠溶片、INR、布洛芬各解释了 | 同样解释；额外把房颤→防中风讲了（来自档案） |
| 多说的 | 无 | 举「芬必得」当布洛芬例子——原文没有（hint 不能根治编造，只把该保的钉住） |

## 8. 总结论

1. 小模型放对岗位是这一天的全部差别：安全闸门需要 gold + 全套纪律，四周零交付；DSP hint 岗位错了只掉质量，silver 够用，一天发布。
2. 0.8B 读析器成立：core80 题级 55:21、忠实 +92，拿到 oracle 上限的大部分；增益全在「不丢数字、不改数字、不漏关键信息」，可读性基线已饱和不受影响。
3. 判读纪律有实测支撑：噪声底 17:22 说明 21:13 幅度不算证据；判据预注册后差 1 题不改判据只加样本；基础设施截断当故障重跑并留痕。
4. 训练侧零新设计：eqreader v4 的训练脚本 / probe / Modelfile / pod 脚本原样复用，13 分钟收敛。
5. 工程副产品：推理模型 thinking 吃光预算 → 空输出/截断，一天踩四次（deepseek max_tokens 32、ollama num_predict 256、标注 4,000、生成 8,000），每次表象都是「模型不行」，靠看原始返回拦住；分级升额度重试已进 translate.py。
6. 费用硬门：deepseek 抽取类任务关 thinking 便宜 60×（同条 63 tok/3 s vs 3,844 tok/40 s）；每 batch ≤ ¥5，脚本记账自停（app/cost.py），写进 finetune-gguf 北极星推论二。
