# 复盘：从「零交付」到「小模型发布」的一天 —— rxreader 医嘱读析器

> 日期：2026-08-17　项目：elder-trans-run1（适老化医嘱翻译器）
> 产物：HF 公开模型 [chenhaodev/rxreader-qwen3.5-0.8b](https://huggingface.co/chenhaodev/rxreader-qwen3.5-0.8b)　代码：github.com/devhc123/elder-trans-run1（私有）

## 一、背景：为什么会走到「29 张票、64 个 commit、0 个能用的东西」

产品目标一直很简单：**医嘱 → 老年人听得懂的话**，小模型 + 大模型两段配合。

但前 29 张票把小模型放在了**最难的岗位**上——「段 B 红线判定器」（判大模型的转译有没有编造/漏关键信息，漏报硬门 ≤5%）。安全闸门需要 gold 标签、正负例分布配平、捷径探针、教师交叉复核……每一步单看都对，但那是**验收一个安全闸门**的纪律，不是**发布一个翻译器**的步骤。

用户当天的判断：「小模型+大模型应该可以达到很好的效果吧？怎么搞得这么复杂？先发布小模型再说，学习下 eqreader。」

## 二、转向：抄 eqreader 的形态，不是抄它的领域

[eqreader](https://huggingface.co/chenhaodev/eqreader-qwen3.5-0.8b) 是同一作者之前发的 0.8B 模型：读对话、抽承载情绪的关键短语、注给大模型当前置提示（DSP）。值得抄的四点：

1. 小模型只干一件**可校验的窄活**（抽原文逐字子串）——错了编排层直接丢弃，不伤安全
2. 大模型干生成，小模型输出只是前置提示，**空则不注入**
3. 验收就一个数：40 题盲评 A/B 胜负
4. 模型卡 = 一个端到端实拍 + 三行安装 + 三条编排规则

对应到医嘱翻译器：**rxreader** 读【背景】老人档案 + 【医嘱】原文，输出两栏逐字子串：
- `保留:` 剂量/次数/时间/禁忌数字 → 管忠实性
- `解释:` 老人听不懂的术语 → 管可读性

关键洞察：**hint 岗位错了只掉质量不伤安全**，所以 silver 标签（大模型打的）就够用，不需要 gold。这一条直接把 29 张票的纪律性工作从「发布前置」变成「发布后可选」。

## 四、判读纪律：几个具体的「怎么读数」

- **先测噪声底再谈胜负。** 同一 prompt、同一模型跑两次互判是 17:22——意味着 eqreader 那种 21:13 幅度在本任务上是噪声。所以判据预注册为「40 题 3 判官题级多数票 ≥27:13 **且**忠实维度净胜 ≥20，达不到加到 80 题再看，不加判官」。
- **判据不动，动样本。** core40 拼接后 26:11（平 3），字面差 1 题（虽然净差 +15 已超 27:13 的 +14）。没有改判据、没有重跑判官，按预注册后备扩到 80 题 → 55:21。
- **基础设施故障不混进结果。** 医嘱转译-007 的 hint 臂被 thinking 吃光 8000 额度、正文半句截断，判官 3:0 判输。按 harness 既有规则（截断不得混进正常样本）重生成一次、只重判该题、原始文件保留、过程写进票据。
- **判官与生成同源（都是 deepseek）**：配对设置下两臂同受自偏好，只读相对胜负，不读绝对分。
- **可读性在基线上已饱和**（strict 达标率 1.0），所以 hint 的主战场是「说得对且全」——事先讲清楚，免得拿可读性当证据。

## 五、事故与教训

### 💸 deepseek 一个 batch 烧了 ~¥48

- 标注器沿用 harness 默认（thinking 开、max_tokens 12000），12 并发起跑，**没先算账**。
- 每条 completion ~3.9k token，**reasoning 占 95%**；deepseek 当天 16:00 UTC 起改峰谷计价，峰时（06–10 UTC，正是跑的时段）输出 $1.32/M。1,311 条 ≈ ¥48，账户余额只剩 ¥43 时被用户发现。
- `"thinking": {"type": "disabled"}` 后同一条 **63 token / 3 秒 vs 3,844 token / 40 秒，输出等价**——便宜 60 倍。剩余 632 条 ¥0.99 跑完。
- 落地：标注器默认关 thinking、逐条记 usage、`--budget-cny` 默认 ¥5 超了自停；随后 `translate.py`/`ab_judge.py` 也接上共用的 `app/cost.py` 预算门（滚动提交、超预算截停、结果标「部分」）。写进 finetune-gguf skill 北极星「推论二：每 batch ≤ ¥5（硬门）」，三条规矩：抽取任务先关 thinking / 先跑 20 条读 usage 再定量 / 记账+自停+挪谷时。

**同类坑当天踩了四次**：推理模型的 token 预算被 thinking 吃光 → content 为空或截断 → 表象是「模型判不出来 / 输出差」。deepseek max_tokens=32（ticket 29）、ollama num_predict=256（ticket 29）、标注器 max_tokens=4000（13/40 空）、生成 max_tokens=8000（1/40 截断）。**失败长得像结论**，每次都靠看原始输出才拦住。

### 🖥 RunPod 第一台空转 5 分钟被自动删机
- 旧 pilot 脚本里 `runpodctl get pod <id>` + grep `"22/tcp"` 的 SSH 解析**从来没真跑通过**（ticket 14 一直停在「RunPod 需用户确认」）。
- 改走 REST API（`publicIp` + `portMappings["22"]`），加本地脱离会话的 90 分钟硬线删机。第二台一次成功。
- 镜像名也错过一次（少了 `-cudnn`）——从 med-risk-run2 的记录里找到正确名字。

### 🔧 其他小坑
- 标注器最初只在结束时落盘——两小时批量不能这么干，改逐条追加+可续跑。
- 短语里的全角逗号「1，25羟基维生素D3」被当分隔符切开——分隔符只认「、」。
- 语料跨库同文：record_id 隔离之外还要按原文查重（剔了 13 条）。

## 六、可复用的原则（一句话版）

1. **先问「小模型该干哪个活」，再问「怎么训」。** 放在错了只掉质量的岗位（DSP hint），silver 就够；放在安全闸门，才需要 gold + 全套纪律。
2. **每一步都交付能跑的东西**，纪律性工作放在发布之后当可选加固。
3. **先花 $0 测天花板**（oracle hint / 零样本对照）再花钱训。
4. **先测噪声底再定判据，判据预注册，不够就加样本不加判官。**
5. **大模型 API 先算账再起跑**：抽取任务关 thinking；每 batch ≤ ¥5；脚本记账自停。
6. **推理模型的空输出/截断先当基础设施故障查**，看原始返回，别当结论。
7. **抄一个跑通过的形态**（eqreader 的训练脚本、Modelfile、pod 脚本、模型卡结构）比从头设计快一天。
