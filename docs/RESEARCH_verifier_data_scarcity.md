## 一、盘内数据速查（三个此前没人算过的数字）

### 1. 违规实例的红线分布：红线 0 占 82–85%，红线 1 几乎不存在

| 切分 | fail 案例 | 违规实例 | 红线0（类别→具体值） | 红线1（说反） | 红线2（编数字） |
|---|---:|---:|---:|---:|---:|
| train 1456 | 66 | 68 | 56 (82.4%) | 1 (1.5%) | 11 (16.2%) |
| holdout 499 | 149 | 151 | 128 (84.8%) | 1 (0.7%) | 22 (14.6%) |

**含义**：把「红线判别」重定义为「红线 0（+ 红线 2 的数字变体）」的窄子任务，
覆盖 ~99% 的违规实例；红线 1 全池只有 2 例，任何训练方案对它都无统计意义，
只能靠规则/教师兜底。这直接支持 L2 的方向。

### 2. FN 剖面：模型对红线 2 全盲，对红线 0 漏一半

150 条网格子集（gold fail 案例，case 级配对；官方 `eval_verifier.py` 口径是
instance 级 18 TP/28 FN，与此处 case 级 19/26 的微小出入源于口径不同，定性一致）：

| 配置 | 红线0 抓/漏 | 红线2 抓/漏 |
|---|---|---|
| 2B factor=5 | 19 / 19（漏 50%） | **0 / 8（漏 100%）** |
| 4B factor=5 | 18 / 20（漏 52.6%） | 1 / 7（漏 87.5%） |

FN 案例的 gold evidence 有清晰的两类模式：**具体药名/食物枚举**
（二甲双胍、庆大霉素、牛奶豆制品、玉米小米）和**具体数字/时长**
（24小时内、4斤、每次十来分钟）。都是「answer 里出现了 source 没有的具体词/数」
这一个机械模式的实例。

### 3. 规则基线：召回几乎达标，精度稀烂——正好是「候选生成器」的形状

用现成 `lexicon/jargon.txt`（≥3 字条目 39,497 个实体名）+ 阿拉伯数字正则，
零训练，holdout 全量 499 条：

| 规则（case 级） | 漏报率 | 误报率 |
|---|---:|---:|
| R1 词表越界（answer 有、source 无的实体词） | 11.4% | 68.9% |
| R2 数字越界（answer 有、source 无的数字） | 57.7% | 31.4% |
| **R1∪R2** | **7.4%** | **78.3%** |

对照：训出来的 2B/4B 模型漏报 60.9%。**两行正则 + 一个现成词表的召回比五组
GPU 训练好一个数量级**，只是精度不能用（78% 误报）。官方 instance 级口径
（R1→红线0、R2→红线2 映射）：漏报 15.2% / 误报 31.1%。

规则漏掉的 case 也全是两类可修的模式：**食物/日常名词枚举**（鸡蛋羹、豆腐、
鲤鱼——不在医学词表里）和**中文数词**（三千分之一、三天、一两个小时——正则只
认阿拉伯数字）。⚠️ 污染纪律：这个观察来自 holdout 的 miss 检查，后续词表扩展
/正则改进必须只在 train 切分上调，holdout 每个冻结配置只评一次。

### 4. span 级样本量测算（两段式的关键红利）

全池 1955 条：规则抽出 **5,602 个候选 span**（均 2.9 个/case），其中
**223 个候选命中 gold evidence**（≈span 级正例，分布在 146 条 case）。
对比 case 级只有 66 条训练正例——**改成逐候选二分类，正例数 ×3.4，且每个
判定的语义范围从「整篇 JSON 联合判断」缩到「这个词在原文有没有依据」**。
再叠加合成扩充（L1：最小编辑对），正例池可到千级——按 L3 的文献水位
（可行区 ≥500–1500）刚好够到。

## 二、文献核对结论（详见 LITERATURE.md，此处只取决断）

- **L1（合成正例）**：做。红线 0 高度模板化，恰是 FactCC 系规则合成战绩最好的
  地形；设计必须是**最小编辑对**（防 arXiv:2606.01304 的来源伪影）+ **真实-only
  验收池**（防合成分数虚高）；真实锚定的边际收益个位数 pp（SAFE 消融）。
- **L2（窄子任务重构）**：做。红线 0 在文献里有专名（factually correct but
  unsupported），MiniCheck（770M 达 GPT-4 级、纯合成训练）与 LettuceDetect
  （encoder token 级分类头 F1 79.2）证明路线可行；但中文无现成模型，任务定义
  可外推、权重不可白嫖。已知反向风险：LLM 判别器的医学知识会把「医学正确但
  越界」系统性放行——验收必设对抗子集。
- **L3（战略水位）**：66 条正例比一切已知可行配置低 1.5–2 个数量级，**红线正例
  <500 不再立项任何微调轮**；短期可用性走教师在线判（固定 rubric + 抽检一致性），
  中期靠 L1 合成把正例扩到 ≥1000 再谈重训。

## 三、综合建议：两段式重构（ticket 12 草案的核心）

```
answer ──► 段A 规则候选抽取（词表∪数字∪中文数词，召回优先）──► 候选 span 列表
                                                          │
             段B 逐候选判定「该词/数在 source 里有没有依据」◄──┘
             （短期：教师在线判；中期：合成扩到千级正例后训 encoder 分类头）
```

- **段 A 已被盘内数据验证**：现成词表+正则召回 92.6%（case 级），补食物词表
  与中文数词正则后有望过 95%；它不需要学习，天然零漏报偏置。
- **段 B 把不可学的问题变成可学的**：判定粒度从整篇缩到单词，正例从 66 →
  223（真实）→ 千级（+合成）；即使不训练，教师只判候选（均 2.9 个/case，
  prompt 极短）也比教师全文判便宜。
- **红线 1（说反）不进这个管线**：全池 2 例，无统计意义，由教师全文判兜底
  （它在 verifier 的 JSON 输出里保留，但不再指望蒸馏学会）。

三个此前方案没有的性质：漏报下界由规则段保证（可审计、可枚举失效模式）；
样本效率红利来自任务重构而非调参；每一步都有独立的文献先例 + 盘内实测支撑。

## 四、明确不做（ticket 11 已实测 + 本轮文献加固）

- 66 条正例上的任何再训练（过采样网格、loss 加权、换更大基座）——ticket 11
  实测 + L3 水位判定，双重判死。
- 直接拿英文现成 checker（MiniCheck/LettuceDetect 权重）零样本用于中文——
  L2 已知跨语言显著退化，只借方法与合成配方。
- 自由改写式 LLM 合成违规样本——L1 已知来源伪影风险，只用最小编辑对。
