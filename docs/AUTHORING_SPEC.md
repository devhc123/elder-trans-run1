# 测试集撰写规范（AUTHORING_SPEC）

> 关联票据：`.scratch/elder-trans-harness/issues/04-scenario-taxonomy.md`（场景与配比）、`06-author-testset.md`（撰写）
> 归类结果原始数据：`docs/faq_classification.json`（逐条可查）
> 复现：`python3 pipeline/classify_faq.py --show-all`

## 1. 场景体系：8 个父类不动，12 个子场景挂靠

项目书第六栏的指标说明是**逐个列举**父类的：「覆盖理解域（检验报告解读、医嘱转译、用药说明、健康科普）与推荐域（权益匹配、分科医生、复诊提醒、用药干预）场景总数」。

因此父类名**逐字保留、一字不改**，测试集要的生活化细分做**子场景挂靠**。这样评审拿指标说明逐条核销时，8 个父类都交得出题；而题目实际难度与语域按适老方向走，不必走修改指标说明的流程。

| 子场景 | 父类（项目书原文） | 域 | 说明 |
|---|---|---|---|
| 检验报告解读 | 检验报告解读 | 理解 | 化验单指标、参考范围、风险分级 |
| 医嘱转译 | 医嘱转译 | 理解 | **无真实语料**，见 §5 |
| 用药咨询 | 用药说明 | 理解 | 这药怎么吃、什么时候吃 |
| 日常照护 | 健康科普 | 理解 | 某症状怎么办 / 怎么缓解 / 怎么预防 |
| 急症处置 | 健康科普 | 理解 | 跌倒、烫伤、卡喉、晕倒等老年高危 |
| 饮食营养 | 健康科普 | 理解 | 忌口、补什么、能不能吃 |
| 运动与养生 | 健康科普 | 理解 | 锻炼、作息、睡眠、节气养生 |
| 科普辟谣 | 健康科普 | 理解 | 「是真的吗」类对抗性提问 |

**子场景数 12**，KPI-2「适老场景覆盖数」目标 10、挑战档 ≥9，故 12 为超额达成。

## 2. 配比依据：真实频次，不是难度

**这是本项目最容易被一句话击穿的地方，所以依据必须写死在这里。**

测试集往生活化、易度更高的方向调，这件事的性质完全取决于依据：按真实用户需求分布配比是**需求对齐**；挑简单的题是**指标造假**。两者外形一样。

依据是 `eqbench-run2/SOURCE/AI健康管家-常见问题.xlsx`——线上真实日志按频次聚合的 Top 150，每条前缀带 `[频次:N]`，**总频次 16,210**。

### 2.1 剔除

26 条剔除（频次 2,676），四类：

| 类别 | 条数 | 理由 |
|---|---|---|
| 儿科 | 18 | 非本项目受众（小孩哭闹、儿童退烧药等） |
| 产品功能 | 5 | 不是健康咨询（"打开我的健康档案"、体重目标提示语） |
| 孕产 | 2 | 非本项目受众 |
| 无效 | 1 | "你好。" |

保留 **124 条 / 频次 13,534**。

### 2.2 ⚠️ 主依据用老年子集，不是全量日志

**这份日志不是老年专属的。** 保留的 124 条里，只有 **43 条（频次 4,560）**明确提及老人/老年或属于老年高发慢病；其余 81 条是差旅（"出差住酒店皮肤痒"）、职场（"办公室空调吹得头痛"）、通用睡眠评估等——它来自一个**通用**健康管家，不是银发产品。

用它直接论证「老年场景配比」有先天缺陷。所以做了敏感性检验：用全量与老年子集各算一遍配比。

**结果差异显著，最大差值 12 题：**

| 子场景 | 全量参照 | 老年子集（采用） | 差 |
|---|---:|---:|---:|
| 饮食营养 | 23 | **35** | **+12** |
| 科普辟谣 | 21 | **15** | **−6** |
| 运动与养生 | 29 | **24** | −5 |
| 检验报告解读 | 20 | **24** | +4 |
| 分科导诊 | 21 | **18** | −3 |
| 其余 7 类 | — | — | ≤2 |

老年人群里**饮食营养的权重明显更高**，辟谣与运动更低。这不是噪声，是人群差异。

**采用老年子集为主依据。** 理由：数据多但人群错 vs 数据少但人群对，本项目要论证的是「老年需求分布」，后者才支撑得起这句话。43 条对应 **4,560 次真实提问**，不是 43 个孤例。全量配比作为稳健性参照一并留档。

每类**保底 15 题**。保底的存在是因为父类必须全覆盖：权益匹配与医嘱转译在日志里频次为 0，但项目书列了它们，测试集不能空着。剩余 90 题按老年子集的频次份额分配。

**「为什么日常照护和饮食占比高、医嘱转译占比低」的答案是频次分布，不是难度。** 医嘱转译拿的是保底 15 题，因为真实老年用户几乎不问这个——他们问的是"这药忘吃了怎么办"。

## 3. 三层分工：频次定题 / 指南定答案 / rubric 定判分

| 层 | 来源 | 职责 |
|---|---|---|
| **问什么** | AI健康管家 FAQ（本文档 §2） | 场景划分与题数配比 |
| **答案是什么** | `医疗AI大礼包-Part1/医学期刊和文献/` 10 份权威指南（老年 2 型糖尿病、衰弱共识、轻度认知障碍、高血压、心衰、房颤、CKD 营养、慢阻肺）+ termonline 医学名词 | `key_points` 的事实底座、`negative_rubric` 的红线依据 |
| **怎么打分** | `eqbench-run1/SOURCE/rubric_core3.yaml`（同理心 / 校准顺从 / 专业信任，0–20 锚点，含 `elder_communication` 子项） | 判官 rubric 骨架 |

源文本主体取自七个爬虫库（索引 83,730 条逻辑记录），逐条 provenance 记到 `record_id`（形如 `bdyd_疾病#row1234`）+ 取用字段名。

## 4. 每题的构成与硬约束

```
persona     老人画像：年龄、文化程度、居住情况、慢病与在用药
query       老人或家属的口语请求，内嵌需转译的原文或数值
source_text 专业原文，逐字取自爬虫记录，不改写
key_points  应覆盖的要点，判官逐点判 covered
negative_rubric 红线，any-violated 即失败
difficulty  易 / 中 / 难，人工判定
provenance  record_id + 字段名 + 库名
```

**难度配比 易 40% / 中 45% / 难 15%。** 难题不是负担而是判别力的来源——若全集偏易，所有模型跑出来差距落在噪声里，这套 harness 就只能交 KPI、没法回答任何「改动有没有用」的问题。难度=难的那 15% 单独切成 `hard` 子集固定报分。

**必须继承的反谄媚约束。** EQbench 的 rubric 专门论证过「顺从性直接计分会奖励谄媚——在健康场景中危险（被『别小题大做』劝退＝放过红旗）」。题目调生活化之后，模型顺着老人说话的诱惑更大，**这条红线比原来更重要**，要在 `negative_rubric` 里显式覆盖。

## 4b. 候选筛选的两道排除表

老年导向筛选按关键词匹配病名/药名/指标名，但**关键词不区分人群、也不区分场景
类型**，于是两类东西会混进来。两道排除表都是在撰写 agent 实际用数据时暴露出来
后补的——schema 校验查不出这类语义问题。

**人群排除（`EXCLUDE_POPULATION`）。** 「贫血」「糖尿病」「低血糖」命中了，但记录
讲的是小儿、早产儿、妊娠期。实测 270 条抽样里污染 **15 条（5.6%）**：小儿α-地中海
贫血、早产儿贫血、妊娠期糖尿病、新生儿高血糖症、胎盘早剥、空腹血糖（产检）等。

刻意**不排除**「先天性」「遗传性」——先天性甲减、遗传性血色病这类，八十岁的老人
一样带着，排除它们是另一种错误。

**急症类型排除（`EXCLUDE_EMERGENCY`）。** 急救库里混着野外/工伤/职业暴露类急症，
它们的**正文**会提到「昏迷」「出血」「呼吸困难」而被老年词表捞进来，但类型本身
与老年居家场景无关：断指急救、海蛇咬伤急救法、砷中毒急救法、高原反应处理方法、
蝎子蛰伤急救。

一个实现细节值得记：「蜇/蛰」是异体字，记录里两种写法都用（"蜂蜇伤" vs
"蝎子蛰伤"），排除表必须两个都列，否则会漏。

## 4c. 各场景候选池余量

抽样优先取**记录名命中**的候选（「二甲双胍片」的用法用量，质量高于某个冷门药说明
里恰好提到「糖尿病」）。但这只在池子富裕时办得到。

**急症处置的池子是真薄**：急救表全库仅 276 行，落进 test 池约 55 条，两道排除后
剩 38 条，而该场景需要 21 题——余量不足一倍，无法只挑记录名命中的（那样只有 13
条）。所以这一类连正文命中一起收，质量靠排除表而非命中方式保证。

`运动与养生` 是另一种情况：穴位叫「三阳络穴」「颊车穴」，记录名天然不含老年词，
真正的信号在功效正文（该穴位主治失眠/高血压）。对这类场景用记录名命中率衡量质量
是错误的口径。

## 4d. ⚠️ 原文基线过高：31% 的题「照抄原文」即通过

冻结后对 270 题的原文逐条算了 strict 可读性，结果必须写在最显眼的位置：

| | 值 |
|---|---|
| 原文 strict 中位 | **0.864** |
| 原文已 ≥0.90（KPI 目标）的题 | **83 / 270 = 31%** |
| 原文 <0.80 的题 | 41 / 270 = 15% |

**这意味着 KPI-1 在近三分之一的题上没有区分度**——一个把原文原样吐出来的系统就能
通过。按场景看，重灾区是占比最大的两类：

| 子场景 | 原文中位 | 已达标 |
|---|---:|---|
| 急症处置 | 0.911 | 13 / 21 |
| 日常照护 | 0.904 | 26 / 47 |
| 复诊与随访 | 0.886 | 8 / 17 |
| …… | | |
| 分科导诊 | 0.823 | 2 / 18 |
| 运动与养生 | 0.824 | 1 / 24 |

原因不难理解：疾病库的「日常」「护理」段本来就是写给患者看的，语域已经偏白话；
真正术语密集的是禁忌、相互作用、检验指标那几类。

**处理方式（不是回避）：**

1. 每题都记上 `source_readability` 字段，冻结数据里可查。
2. 跑数时**必须同时报「净提升」**（转译后 − 原文），并单独报「原文未达标子集」
   （187 题）上的达标率——那才是真正测转译能力的部分。
3. 绝对达标率仍是项目书写死的 KPI-1，照报，但**不得单独引用**。宣称「我们把
   可读性做到 90%」而不提原文基线 0.864，是在夸大能力。

**为什么不换掉这 83 题：** 它们反映的是真实源数据分布——产品线上遇到的文本就是
这个样子，其中相当一部分本来就不难。人为只留难题会让测试集偏离真实分布，那是
另一种失真。正确的做法是把基线一并披露，而不是挑数据。

## 5. 诚实披露

1. **日志人群不匹配。** 全量 124 条里仅 43 条老年特异，主依据已切到老年子集，但其 n 偏小（43 条 / 4,560 频次）。这是本配比最大的不确定性来源。
2. **医嘱转译无真实语料。** 全盘（公开数据 + 本地 10 条数据源）**没有任何真实医嘱单、处方笺、出院小结**。该类只能用疾病库「治疗/就医」字段模拟，**对外一律表述为「治疗方案转译」，不得宣称是真实医嘱**。
3. **权益匹配的医保侧是空白。** 爬虫库只有 `yibao_status` 布尔位与 `cost_money` 粗估，无医保目录、报销比例、起付线、门诊慢特病政策原文。该类 15 题只能围绕「是否医保内」这一粒度出题，或需外部补数据。
4. **归类是关键词规则，不是模型判断。** 规则顺序即优先级，写在 `pipeline/classify_faq.py` 的 `RULES` 里。这样做是为了让归类结果可复核、可争论、可修改——这份配比要拿去答辩。代价是边界样本会有归错，`--show-all` 可逐条核。
5. **日常照护是兜底类。** 47 题里相当部分来自规则未命中的兜底，其内部同质性弱于其他类别。
6. **急症处置候选余量不足一倍**（池 38 / 需 21，见 §4c）。该场景的题目多样性受源数据限制，若后续要扩题量，必须先补急救类数据源。
7. **两道排除表是事后补的，不是设计时就有的。** 它们由撰写 agent 在实际用数据时发现——schema 校验能查泄漏、查 provenance、查长度，但查不出「这条记录的人群对不对」。语义层面的数据质量得靠真正去用它的人（或 agent）。这意味着现有排除表**大概率仍不完备**，后续每一轮使用都应留意新的误收类型。
